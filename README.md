# Finance bot

Учёт трат и доходов в Google-таблице. Реестр пользователей, приглашения, ввод кнопками.

## Локальный запуск

```bash
cd finance-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# в .env вписать BOT_TOKEN и BOOTSTRAP_CODE
# credentials.json положить рядом с .env

python -m bot.main
```

## Проверка

1. `/start` → «Создать учёт»
2. Ввести код из `BOOTSTRAP_CODE`
3. Прислать ссылку на таблицу
4. Выбрать базовый набор категорий
5. `/status` — должно показать таблицу и участников
6. Открыть таблицу: появились листы `transactions`, `categories`, `recurring`
7. `/invite` → код → девушка вводит `/join КОД`
8. Кнопка «Трата» → категория → сумма → операция в листе `transactions`
9. Отправить просто `500` — бот спросит только категорию
10. `💬 Комментарий` под записанной операцией, `/last`, `/undo`, `/repeat`
11. `/recurring` → «Добавить» → тип, категория, сумма, расписание, название

## Команды

| Команда | Что делает |
|---|---|
| `/add`, кнопка «Трата» | записать трату |
| `/income`, кнопка «Доход» | записать доход |
| `/last` | последние 10 операций |
| `/undo` | удалить последнюю свою |
| `/repeat` | повторить последнюю |
| `/recurring` | постоянные операции: аренда, подписки, зарплата |
| `/invite` | код для второго участника |
| `/categories` | список категорий, перечитывает таблицу |
| `/status` | что подключено |

Суммы понимаются гибко: `1500`, `1 500,50`, `1.5к`, `300+450`.

## Категории

Лист `categories`, колонки: `name`, `type`, `emoji`, `order`, `active`, `manual`.

- `active = FALSE` — категория выключена везде
- `manual = FALSE` — не показывается на кнопках ручного ввода, но остаётся
  доступной для постоянных операций. Для аренды, интернета, кредитов: платёж
  записывается сам, а кнопка не мешается под рукой
- `order` задаёт порядок кнопок

Правится руками в таблице, бот перечитывает после `/categories`.

## Постоянные операции

Живут в листе `recurring`. Планировщик просыпается каждые 30 минут. Два расписания:

**Каждое число месяца** (`schedule_kind = monthly`) — аренда, зарплата, коммуналка.
Записывается, если нужное число уже наступило, а отметки `last_posted_month` за
текущий месяц ещё нет. Поэтому пропущенный день не теряется (бот лежал 1-го —
запишет, когда поднимется) и не задваивается при перезапусках. 31-е число в
коротком месяце превращается в последний день.

**Каждые N дней от даты** (`schedule_kind = interval`) — линзы, стрижка, всё с
циклом не в месяц. Следующий срок считается от `last_posted_date + interval_days`.
Пропущенные периоды не досчитываются: запись делается один раз, и отсчёт идёт
от неё. То есть если бот молчал две недели при цикле в 7 дней, будет одна запись,
а не две.

Операции помечаются `source = recurring`, в комментарий попадает название.
Выключить на время — кнопка в `/recurring`, строка в таблице остаётся.

Новые колонки в листах добавляются только в конец, а структура догоняется при
старте бота — уже записанные данные не съезжают.

## Полезное

- `/sa` — покажет email сервисного аккаунта, если забыл, кому давать доступ
- Категории правятся руками в листе `categories`, бот подхватит после `/categories`
- Суммы внутри кода — в копейках (`int`), в таблице — в рублях
- `credentials.json` и `.env` в git не попадают (см. `.gitignore`)
- На хостинге вместо `.env` используются файлы в `/app/data`: `bootstrap.txt`, при необходимости `bot_token.txt` и `allowed_users.txt`
